# archive/ — 历史过程产物归档

> **这不是垃圾桶。** 这里保存的是 BoothKeeper 从 v1.0.0 到 v1.5.6 期间用于
> 「修复某一轮问题、验证某一轮改动、渲染某一轮预览」的一次性脚本与中间文档。
> 它们已从仓库根目录迁入此处，**保留 git 历史，可随时查阅当时的做法**。

## 为什么归档

仓库运行到 v1.5.6 时，根目录累计散落了 30 个脚本 + 23 份 md + 1 份 html。
后果有三个：

1. **接手者分不清主次** —— 新会话/新机器/新模型打开仓库，无法判断
   `booth_core.py`（本体）与 `test_qa_r5_real.py`（一次性验收）哪个是活的。
2. **`.gitignore` 自相矛盾** —— 同类文件出现「一半入库、一半被忽略」，
   因为旧规则无前导斜杠，`git status` 呈现的真相被掩盖。
3. **本地与远程不对称** —— 17 项文件既未入库也未声明忽略，长期悬空。

归档后根目录只保留**运行必需 / 打包必需 / 入口文档**，规则写入
`.gitignore`（全部以 `/` 开头，只约束根目录）。

| 目录 | 内容 | 数量 | 说明 |
|---|---|---|---|
| `scripts/` | 一次性修复 / 预览渲染 / 离屏测试 / 巡检脚本 | 30 | 按轮次命名（`_rN`、`_test_*_rN`、`fix_rN_*`），含 `assets/art` 的素材生成脚本 |

| `design/` | UI 设计简报、旧主题备份、作者卡片模板 | 4 | `design_brief.md` 是 UI 重构评审 Rubric；`theme_v1_backup.py` 是旧主题快照 |

## 怎么用

查某轮改动的原始实现：

```bash
# 按轮次列出相关脚本
ls archive/scripts | grep -i r12

# 查某个已经不在根目录的旧脚本的完整历史
git log --follow -- archive/scripts/fix_r12_consolidate.py

# 看某轮到底改了什么
git show HEAD --stat -- archive/
```

## 维护约定

- **新增过程产物一律写入本目录，不得散落根目录。** 根目录的对应规则已在
  `.gitignore` 中声明，散落文件会被忽略（即不会入库，也就不会污染远程）。
- 归档**只搬运、不改写**：脚本内容保持原样，不"顺手修一下"。若需把某个
  归档脚本正式纳为工具，应另起改动将其移入 `pages/` 或独立 `tools/`，
  并在此处注明去向。
- 若某轮产物的价值已被 worklog 与 plan 完整覆盖，可在确认后删除，
  但删除前需在 `docs/boothkeeper/v1/worklog/` 留痕。
