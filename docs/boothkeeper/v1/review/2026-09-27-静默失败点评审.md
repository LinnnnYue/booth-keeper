# 静默失败点评审（R17）

> 用途：P2「评审 `archive_util.py` 的静默失败点，改为至少记录到 worklog 或 UI 状态」的**验收记录**。
> 范围：`booth_core.py` / `archive_util.py` / `main_window.py` / `theme.py` / `pages/*.py`。
> 统计口径：`except ...:` 语句下一行紧跟 `pass` 的位置（脚本化提取，非人工抽样）。

**核心判据**：静默本身不是错。只有当「失败后用户可观察到的状态与真实状态不一致」时才是缺陷——
例如「以为设置已保存」「以为目录已有图标」「以为文件已清干净」。按此判据逐处定性。

## 三、判定「建议后续加固」（8 处）

| 位置 | 所属函数 | 现行行为 | 建议 |
|---|---|---|---|
| `booth_core.py` L561 | `isolate_old_versions` | 旧版本隔离失败静默 | 旧版本残留但界面无提示，与「永不删除、只留档」的承诺不符 → 应上报 |
| `booth_core.py` L1071 / L1094 / L1104 | `make_folder_icon` | 图标生成失败静默 | 已由 `archive_util` 侧 `icon_ok` 间接可观测，但**直接从 `booth_core` 调用时仍不可见** → 建议函数内留痕 |
| `booth_core.py` L1147 | `normalize_desktop_ini` | ini 规范失败静默 | 目录图标不生效且无提示 |

> 这批的共同点：**失败后界面呈现的状态与磁盘真实状态不一致**，但单一处改动收益有限，
> 且涉及 UI 线程上报机制（`print` 在打包后不可见）。建议统一设计「后台异常 → 状态栏/日志面板」
> 的上报通道，一次性解决，而非逐处打补丁。

## 四、高危待独立立项（3 处）

| 位置 | 所属函数 | 风险 |
|---|---|---|
| `archive_util.py` L285 | `archive_item` | force 留档失败后还原 `moved` 文件，单个 move 失败被吞 → 可能留下**半还原**状态 |
| `archive_util.py` L312 | `archive_item` | 还原 `old_archived` 失败被吞（含 `rmdir`）→ 可能残留半还原目录却已对外报错 |
| `archive_util.py` L349 | `archive_item` | 移动失败后的还原失败被吞 → 同上 |

**为何不在本轮处置**：这三处位于 `force` 重归档的**回滚路径**，改动需覆盖以下场景的真机演练：

1. 留档中途磁盘满 / 文件被占用
2. 还原途中进程被杀
3. 还原后目录处于「部分旧内容 + 部分已移出」的中间态

在未建立演练环境前改动回滚逻辑，风险高于现状。**留待 P3 独立立项**，届时须先补测试用例再动代码。

## 五、复现方式

```bash
# 统计静默点（与本文口径一致）
python - <<'PY'
import pathlib
targets = ['booth_core.py','archive_util.py','main_window.py','theme.py'] + \
          sorted(str(p) for p in pathlib.Path('pages').glob('*.py'))
total = 0
for f in targets:
    p = pathlib.Path(f)
    if not p.exists(): continue
    lines = p.read_text(encoding='utf-8').splitlines()
    n = sum(1 for i, ln in enumerate(lines)
            if ln.strip() == 'pass' and i > 0 and lines[i-1].strip().startswith('except'))
    total += n
    if n: print(f'{f}: {n}')
print('合计:', total)
PY
```

预期输出：合计 **29**（处置前 36）。
